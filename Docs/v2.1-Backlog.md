  relationships optional with explicit inverses.

## W7 — StreamTimes hand-off

Cross-project. NCDB is where a film is chosen; StreamTimes is where it is scheduled.

Join key is `tmdbID` / `tmdbId` (both `Int?`, both from TMDb). Same development
team, so a shared App Group is a capability tick.

**Apps cannot invoke each other's App Intents** — intents are dispatched by the
system and the type lives in the other app's binary. Three lanes over one
versioned `WatchHandoff` DTO instead:

1. **Shared App Group outbox** (primary) — `group.illitrate-Publicashions.shared`.
   NCDB appends handoffs; StreamTimes drains on foreground. Lossless, batched,
   offline, no app switch.
2. **Deep link** for immediacy — `streamtimes://add?handoff=<uuid>`, referencing
   the outbox entry rather than carrying the payload in query parameters.
3. **Enrich StreamTimes' `AddToQueueIntent`** with `tmdbID`, `runtimeMinutes`,
   `releaseYear`; set `openAppWhenRun = false`. The only true background path,
   and it improves StreamTimes standalone.

Ownership splits by fact type: NCDB owns watch history, StreamTimes owns the
schedule. NCDB sends intent-to-watch; StreamTimes sends completions back. The
`origin` field guards against loops.

Fix while in there: StreamTimes' `MarkAsWatchedIntent` resolves films by fuzzy
title (`contains`, first match wins) and `WatchItemEntity` carries no `tmdbId`.

Cheap trial before committing: chain NCDB's `SuggestFilmIntent` into StreamTimes'
`AddToQueueIntent` in the Shortcuts app. Lossy (title only) but free.
